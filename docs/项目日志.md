# 大周列国志 · 史馆 —— 开发日志（公开版）

> **一句话定位**：游戏《大周列国志》的修谱工具 —— 左手翻游戏存档（实录），右手修家谱（谱牒），中间一座桥。
> **最终目标**：不必再手写家谱 —— 从游戏存档不断自动读取、续写家谱。
> **本文档**：精练的公开版本，记录项目的架构、数据口径、核心机制与开发阶段。原内部总日志的逐条流水（用户原话、逐次自检、临时探针、批次编号）已整合为按阶段的里程碑；只保留对理解「做了什么、难在哪、怎么解决」有用的内容。

---

## 一、这是什么

「史馆」由两个旧项目合并而来：

- **《大周列国志·存档阅览器》** —— 资料库，纯只读（全量存档，9106 人 × 140 表族 × 1004 字段中文化）。冻结为「数据源」。
- **《Family tree v2.0》** —— 修谱台，可编辑（家谱树 / 时间轴 / 表格 / 小传 / AI 识别）。冻结为「谱牒母本」。

合并后的「史馆」取二者本义：**藏史**（实录原样收好，只读不增删）＋ **修史**（在实录之上编一部自己的家谱）。

技术形态：Windows 桌面应用（Python + Tkinter，无第三方 GUI 依赖）。另含一个可选的平板端前端（原生 Kotlin + Compose）。当前版本 **2.0**。

## 二、核心架构：一档 · 两层 · 一桥

```
MuMu 模拟器（com.xinlanzaoyi.ztz.mi）
   │  adb root + pull（sync_from_mumu.py）
   ▼
本地存档 D:\DevCache\dzlgz\Save_All_N（原文，一字不动）
   │
   ├──► 【实录层】 saveload.py 直读（只读铁律：永不落盘）
   │        全量人物 · 多表合并 · 全字段中文化
   │
   └──► 【谱牒层】 import_from_game.py 多步流水线
            → saves/<谱名>/family.json（可编辑：增删改/撤销/续谱）
   ▲                │
   └────── 桥 ──────┘
     · 锚点：family.json 里人的 code = 存档 Ren_Code
     · 入谱：实录某人 → 写入谱牒；查档：谱内某人 → 跳回实录全字段
```

### 两层铁律（不许互相污染）

| | 实录层 | 谱牒层 |
|---|---|---|
| 数据来源 | 存档原文 | family.json（人写 + 导入） |
| 落盘 | **永不** | 正常存取 + 自动备份 |
| 规模 | 全量（几千~上万） | 精选（几百~上万） |
| 视图 | 人物 · 世界 | 家谱 · 时间轴 · 表格 |

### 五大视图

**人物 → 家谱 → 时间轴 → 世界 → 表格**。记忆口诀：先查人，再看族，后看天下，要动笔去表格。
颜色语义：查阅类两页（人物/世界）青绿，编辑类三页（家谱/时间轴/表格）橙金 —— 界面上一眼分清两层。
（后经用户裁定，家谱与时间轴合并为「家谱」页的两种模式「代际 / 时间」，页签由 5 减为 4。）

### 桥的动作

入谱（单人/整支）｜查档｜补全｜对拍｜整谱导入｜世系速览（只读树，不落盘）｜整支入谱。

其中「**世系速览**」是两个旧项目都做不到的动作：对实录任意一人，用家谱画布引擎渲染他的**男性后裔**（父系单传：女儿入谱不下传），纯视图、零落盘。

## 三、数据来源

- **模拟器**：MuMu，包名 `com.xinlanzaoyi.ztz.mi`（小米版）。每步 `start-server → connect → root → connect`，端口 16416。
- **存档路径有一个游戏自身的 bug**：目录名里含反斜杠（`...Save_Files\Save_All_<N>/`），取文件要用单引号包整条路径。
- **加密**：云端下载的槽是 Base64 加密的，读不了 —— 界面上就标「加密」。解法：在游戏里载入它、过一回合自动存档，明文就会写回本地槽。
- **存档是 UTF-8 明文 JSON**；人物记录分散在**多张表**（族谱表 / 活人表 / 已故表 / 女性表，后补齐出生表与旧人物表），抽取时取并集。

### 存档里有什么、没有什么（实测结论）

- **没有剧本名**：全槽原文搜 12 个剧本名 0 命中 —— 游戏没把剧本名写进存档，槽列表里的名字是游戏自己按内容推的。
- **没有存档现实时间**：存档 json 里找不到「2026-09-19 13:09」这类时间 —— 只能趁拉档那一刻从设备目录 mtime 取、落盘存下来。
- **开局年 ≠ 当前年份**：`King_Stage_Record[0].Start_Time` = 该国进入第一阶段那年（≈开局年）；`Save_Zhan_Zheng_Data.Start_Time` = 当前年份。查剧本用开局年，时间轴右端用当前年份。
- **界面字段不在存档里**：爵位/神名/庙名/政策名/能力名等，存档只存裸编号 —— 名字是游戏内置表（含加密表），必须靠截图、攻略、游戏资源转录进代码，否则一旦来源失效即永久丢失。

## 四、硬事实（防坑手册）

这些是踩坑换来的、必须遵守的数据口径：

### 人物判定

1. **史实 / 非史实按编号位数硬分**：`Ren_Code` ≤5 位 = 史实；9 位 `1XXXXXXXX` = 随机生成。不靠猜、不靠白名单。（后修正：**非纯数字编号**如 `QIN001` 是游戏写死的具名人物，同样归史实。）
2. **四张人物表互不重叠**（活人表 ∩ 已故表 = 0）；卒年字段只在已故表里有。
3. **女性仅保留史实或有爵位者**；重名人物只允许加中文序数/数字区分，不加解释性后缀。

### 宗庙与世系

4. **宗庙里有三类非「即位君主」的牌位**：始祖庙（每国 1 位）、追封远祖（无即位时间）、**占位链**（名字带「父/祖/曾/高」后缀，是游戏为凑显示世代造的假人）。151 个宗庙里 143 个只有 6 张占位牌位，只有 8 个国有真实世系。
5. **占位祖先需分辨真假**：判据 = 编号带「父/祖/曾/高」后缀**且记录里没有 `Ren_Sex`（性别）**；姓名匹配不可靠，必须用 `Ren_Code` 关联人物。
6. **世代有三种，含义不同**：牌位 `Generations` = **封国世代**（受封者 = 1）；牌位 `Ren_Generations` = 宗庙连续编号；人物 `Ren_Dai_Shu` = **族谱世代**。早期把族谱世代当成「第几代国君」，导致小传出现「第 80 代」的荒谬数字。
7. **游戏的族谱表 `Jia_Zu_Genealogy` 是宝库**：每行含始祖编号、族谱内世代号与父链，父链自洽率高；也是后来「推定世系/同姓接枝」的依据来源。

### 爵位

8. **爵位只能从尊号读**（`Memorial_Ren_Zun_Hao` 里的爵位字）。`Memorial_Ren_Jue_Wei_New` 是**庙级**码（1=秦庙、3=楚庙…），不是人级爵位码 —— 曾误以为是爵位码，实测大批误判后纠正。
9. **国爵**取自 `Save_KingData.King_Jue_Wei_Code`（如齐=侯、宋=公、鲁=公、楚=子）；**建国年**取自 `Jian_Guo_Year`；势力名照抄游戏（游戏拿氏当势力名，「熊」「将」不映射为历史上的「楚」「秦」）。

### 编号与映射

10. **编号映射优先用存档反解**，不要用眼睛：`Save_KingData.King_Buff_Array` 的授予记录同时带编号与游戏写入的中文名（`Buff_Name`），可自动反解出「编号 ↔ 名字」。
11. **政策树**在 `Save_KingData.Zheng_Ce_Shu_Array`：按流派分组，`Code = 政策编号 + 2000`。部分军制编号是「参数化」的（同一编号在不同军里显示不同名字），**不进映射表**，改由实例自带 `Buff_Name` 渲染。

### 字段与显示

12. **存档字段名是拼音**：扫字段别用中文关键词（中文只出现在**值**里）；找身份类字段最快的筛子是**「字段出现率」**（稀有字段 ≈ 少数人才有的属性）。
13. **「0」有语义的数值字段**：等级 `0` = 「庶」、智略 `0` 是有效值 —— 判空不能写 `v not in (None, "", 0)`，此处本项目被咬过数次。
14. **卒年字段**：`Ren_End_Time`（真实卒年）与 `Ren_End_Old`（享年）；在世者只有享年。卒年可用「生年 + 享年」推算，但真实卒年优先。
15. **义子无专门字段**：游戏不记「义子」，义子就是挂在 father 名下的普通子女（多为非史实的随机人物）。
16. **解释性括号文字一律走 tooltip**，正文只留主体。
17. **列宽按内容自适应**（`kit.est_text_px` 估算，故意偏大 8%，宁宽不切），禁逐行量整表；表格列宽按**典型值（分位数）**定，极端长值交给详情卡。
18. **临时脚本一律写进 `_scratch/`**（出过一次「D 盘根目录散落脚本」的事故）。

## 五、核心机制：续谱

### 流程

```
续谱对话框里选一个实录槽（可顺带从模拟器拉档）
   → 读槽里的剧本开局年 + 争霸类型（号段）
   → 目标谱牒名 =「剧本名·争霸类型」  例：《秦末起义·沙盒全局》《卫氏朝鲜·沙盒局部》
   ├─ 保护档认得出同一个剧本 → 跳过并提示
   ├─ 目标谱牒不存在 → 演习（整档统计，不落盘）→ 写回时自动新建
   ├─ 目标谱牒已存在 → 演习（--merge）→ 写回时增量续写
   └─ 同名谱牒绑在别的槽上 → 冲突：勾「另存为新谱牒《X (2)》」或手动指定
```

写回成功后**自动切到目标谱牒**，实录也跟着切到那个槽。

### 规则

- **只更新新人**（`FACT_KEEP`，判据是「旧记录里有没有这个键」）：老人物的封国/爵位/世系一律保留旧值 —— 用户手改的爵位不被冲掉。
- 生卒 / 性别走补齐式（`FACT_FILL`）；血缘冻结（旧值非空就留）。
- **保护档**（`source.protected`）是用户原始记录，自动续谱跳过；判定**按剧本名对**（两边都过 `scenarios.match_name()`），不比字符串。
- **抽取口径固定一条**：史实 ＋ 续谱名单点名的非史实人物（连同其**纯父系**后裔，不含女儿支）。
- **争霸类型号段**：`1-999` 沙盒全局 · `1000-1999` 争霸模式 · `4000-4999` 沙盒局部 · `5000-5999` 家族模式。
- **剧本名只在同一争霸类型里查**（同一年份不同争霸类型剧本名可以完全不同）。
- **拉档后按新档重算目标谱牒**：只要这次真拉了档，就按槽里现在这份的剧本重推目标。

### 两个容易踩的点

1. 保护档按**剧本名**对，不是按谱牒名字符串比。
2. 新建的「演习」不带 `--save`（只分析不落盘）；0 人的槽演习会失败、写回按钮点不动 —— 不会建出空谱牒。

### 桥的两个按钮（易混，已正名）

- **「立即入谱」**：连同全部男性后裔**立刻**写进当前谱牒档。
- **「预约入谱」**：**不马上写谱**，只把这一支记进「续谱名单」，等下次点「续谱」时才整支抽入。

- **核心诉求「续谱自动产生或更新对应存档的谱牒」落地**：选槽自动定谱牒名、保护档跳过、新建/续写/冲突四分支、写回自动切档；加进度条与不冻窗口。

- 修复四条「假设不牢」的问题：`detect_start_year` 由「读 0 号文件」改为**全档取最早**（+ 缓存）；`scenario_of` 加**向上容差**（秦汉段剧本相邻仅 2~5 年，最危险）；保护档时放开「先演习」；槽列表标注缓存来源。
- 一批纯外观改进（图标、配色语义、弹窗主题统一、排序指示、行高、工具栏减负）；一批代码清理（删除十余处废代码、导入流水线选择性读盘缓存、封国继承由 O(n²) 改 BFS）。

### 阶段三 · 数据层攻坚：编号映射与政策树（2026-09-22 晚）

- 政策/能力/特质显示模块 `names_map.py` 建立：先靠游戏内截图逐张配对（**界面顺序 = 存档数组顺序**），累计实证数百条编号；详情卡把政策/能力/特质渲染成徽标行并带效果 tooltip。
- **决定性突破**：发现存档 `King_Buff_Array` 自带「编号 ↔ 中文名」对照 —— 一条脚本 11 秒拿到 245 条（原口径约需 150 轮人工截图）。此后确立纪律：**编号映射优先用存档反解，同一个键只允许在一处出现**。
- 导出**政策树**结构（30 流派 / 785 编号）：用已知答案的儒家树校准出「游戏界面 ↔ 存档树」的完整对齐规则（支序自树底往上、同列编号自下而上递增、界面会混入邻流派节点需按名字排除），再批量处理 70 张截图 —— 政策树覆盖率一举到 **667/785（85%）**。
- 显式记下两条「死路」以免后人重走：存档**无剧本名字段**、`King_Stage_Record[0].Name`（先民/礼法/方国/圣人）粒度太粗，都区分不了剧本。
- 资料沉淀：把 TapTap / BWIKI 等攻略中的流派政策效果原文转写进效果表（来源标注为二手，数值以游戏内为准）。

### 阶段四 · 世界页效果体系与安卓化评估（2026-09-22）

- **世界页「意义不明」考古**：确认 `King_Buff_Array` 是统一效果表（16 种类别码：政策/能力/祭祀/外交/状态/政体/文物/奇观/天时/技术/兵种……）；纠正 3 处表族名错译（细作/神明·垂临/奇观）、5 处枚举错译；补 54 个未翻译字段；给不显然的表加「它是干什么的」说明。
- 安卓化可行性研究：结论是数据层 100% 与 Tkinter 解耦（探针屏蔽 tkinter 后 `app/` 全部模块可导入并真读档），但 UI 层约 11000 行与 Tk 深度绑定须重写；「读档」受安卓沙箱限制（需 root），「看谱牒」不受限。
- 落地**单文件 HTML 家谱导出**（`tools/export_html.py`）：复用桌面端同一套布局算法（世系结构、连线、夫妻符号一致），主题色直译 CSS 变量，产物零外部依赖，可发到手机离线查阅 —— 也是后续平板端的 UI 骨架。

| 世系框混入非君族者 | 封国/势力/世系口径混用 | 世系框只认君族 + 从始封君起 |

## 九、验收与工程纪律

### 验收

每批改完运行固定套件（后期改为按节奏每若干轮全量跑一次）：

```
python tools/smoke.py            → FAILS 0
python tools/_m1_accept.py       → 全部通过
python tools/_m3_ui.py           → 全部通过
python tools/hotkey_check.py     → FAILS 0
python tools/_m1_bridge.py       → 通过
python tools/_m2_merge.py        → 九条断言全部通过
python tools/_m4_quanshi.py      → 全史存档专项
```

⚠️ 验收脚本会污染 `config.json` 与 `saves/`：跑完必须还原 `config.json`、删掉临时谱牒。**跑 smoke 前把 config 切回轻量谱牒**（大谱牒上快捷键实证会超时）。

### 回滚

- 早期（未 git 化时）：整份备份目录 + 回滚脚本（`_scratch/*_rollback.py`）。
- 现状：项目已 `git init` 并托管在 GitHub（公开仓库 · MIT），改动走提交历史回溯；
  `.gitignore` 与 `config.example.json` 已就位（`config.json` 含 API Key，须排除）。

### 纪律要点

1. 遇到问题**追根因，不打补丁**；每个决策都要能回答「为什么」。
2. **先读后写**：改文件前重新读取目标文件最新内容。
3. 动机或目标不清晰时停下来讨论。
4. 不要过度考虑当前项目不可能出现的边界情况。
5. PowerShell 显式指定 UTF-8；输出与回复一律简体中文；修改优先逐行精确编辑。
6. **界面功能的验收必须走用户真正能走的那条路**（导航行/按钮），不能只验数据层与渲染函数。
7. **布局类改动的最低验收门槛是「截图目检」**，不是「控件存在」。
8. **交付物文件名用 ASCII**：中文名在 Windows 命令行生态到处踩坑。
9. 「藏起来」不是「删掉」：判定死代码的标准是「还有没有不可替代的调用方」。
10. **史馆开着时不要用脚本改 `saves/`**；改完先关史馆再重开。
11. **推定层必须「重建」而不是「增量修补」**（增量会让新旧结果并存且互相矛盾）。
